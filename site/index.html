What Bluetooth Alert is

Bluetooth Alert is an experimental Android app that shows your phone's alerts on a Bluetooth receiver, such as a car stereo, boat or bike audio unit, or a speaker with a screen. It sends a short alert title through the receiver's Bluetooth music screen, and can briefly interrupt music and then resume it. The app checks which functions each receiver supports and only uses the ones that are confirmed to work. In this beta, alerts go one way, from the phone to the receiver; replying by text or voice is not part of it.

Privacy first. The app is a pass-through. It does not store or upload the content of your messages or alerts, and it has no account or cloud service. Anything you send us is something you choose to share by email, after checking it yourself.

You need an Android phone (this APK cannot be installed on an iPhone) and, for the main test, a paired receiver with a screen that shows Bluetooth music titles. Receivers without a display are still useful for testing setup and audio.

Set up and test only while stationary. Park safely before touching either device. Keep volume low. Functions depend on what the receiver supports; text display, remote controls, browsing, or automatic music resumption are not guaranteed. Phone-call audio (HFP/SCO) and LE Audio are not tested by this beta.

New in beta.6

  • Recovery after the receiver loses power or goes out of range. When the receiver comes back within 30 minutes, the interrupted alert should resume with its title and audio. This also works after the app was force-stopped.
  • “Welcome back” after a long gap. If the receiver was away for more than 30 minutes, old alerts are not replayed. The receiver shows only “Welcome back” and a count, such as “2 notifications in Recent Alerts”.
  • Alert audio on newer Android. While an alert plays, Android 8 and later show a “Bluetooth Alert · Delivering an alert” notification that goes away when the alert ends. This is required for alert audio on Android 15.

1. Install and connect

  1. Download on your Android phone. Open this page on the phone, tap the download button, then open app-debug.apk from the browser's Downloads list. If Android asks, allow this browser or file app to install this APK. You can turn that permission off afterward. If installation fails, record the error category in the report below.
  2. Open Bluetooth Alert and note its version. The version is shown near the top of the app and should read 2.0.0-beta.6. Copy it into the report below; if you cannot install the app, use the version on the release page.
  3. Pair normally. Use Android Settings → Bluetooth and the receiver's normal pairing menu. For the first test, disconnect other Bluetooth audio receivers from the phone. On the receiver, select Bluetooth Audio, Media, or the equivalent music source. Phone-call pairing alone may not connect Bluetooth music.
  4. Allow Bluetooth access when prompted. Android may call it Nearby devices. The basic test uses the app's generated test alerts, so notification access is not needed for it.

2. Run the basic test

Use one receiver per report. “Receiver” just means the Bluetooth device you are testing. It is useful to report failures, unavailable buttons, and devices with no screen too.

  1. Find your receiver in the app. Tap V2 Endpoint Capability Inspector, then Refresh bonded endpoints. Select the connected receiver in the list and tap Run available probes. “Bonded” means paired; “probes” means the app's checks of available functions. Unknown or provisional means a function has not been verified yet.
  2. Send a generated title. Tap Send metadata test in the inspector. On the main screen, the equivalent button may say Send Test Alert. Watch the receiver's music/title screen while the test is active. The generated title contains a test number, such as #1 TEST ALERT — ALPHA; sending another test changes the number.
  3. Record what the receiver actually showed. Was the whole title visible, cut short, missing characters, delayed, or absent? A title in the phone's preview does not prove it reached the receiver. Tap Confirm metadata visible only if you saw it on the receiver. Otherwise use the buttons for a missing title, timeout, truncation, or wrong characters. If a test button is disabled, report that and continue with the steps you can run.
  4. Try the receiver's media buttons, if it has them. While a test alert is active, try Play, Pause, Next, and Previous, one at a time. Record each separately as worked, no visible effect, button not present, or not tested.
  5. Check reconnecting. Tap Dismiss alert / Resume media. Disconnect the receiver in Android Bluetooth settings, reconnect it, refresh the inspector, and send another generated test. Record whether it works after reconnecting; do not remove the pairing unless normal reconnection fails.
  6. Check music interruption. Start ordinary music through the receiver, then return to Bluetooth Alert. Select Priority — interrupt media, show alert, then resume, send a test, and dismiss it. Record whether music resumed automatically, needed a manual restart, or did not resume. Stop the test if playback keeps switching between apps.
  7. Save the app's privacy-safe report. In the inspector, tap Export privacy-safe capability report and choose your email app. This creates the text you will attach in step 4.
A speaker with no display can be a useful test. Choose “No display on receiver” in the report. A missing display is different from a receiver with a screen that failed to show a title.

3. Optional: recovery tests (new in beta.6)

These tests check what happens when the receiver disappears and comes back. They need a real notification, because generated test alerts are not kept for recovery. Use a harmless one you create yourself, so no personal content is involved.

  1. Turn on notification access. Tap Grant notification access in the app and allow Bluetooth Alert. You can turn it off again when you finish.
  2. Create a dummy notification. For example, set a reminder or calendar event called Beta test for one minute from now, or ask a friend to text you just Beta test. Leave the notification in place; swiping it away ends the alert. Set the app to Priority so the alert plays with audio.
  3. Short power loss. While the alert is playing on the receiver, switch the receiver off for a few minutes (less than 30), then on again. The same alert should come back with its title and audio.
  4. Quick power flaps. During an alert, switch the receiver off and on three times within one minute. It should reconnect each time, without a duplicate or stuck alert.
  5. Out of range. During an alert, walk out of Bluetooth range for a couple of minutes, then return. The alert should come back as in step 3.
  6. App force-stopped. During an alert, open Android Settings → Apps → Bluetooth Alert → Force stop, then reopen the app with the receiver still connected. The alert should resume.
  7. Long gap, ideally overnight. Interrupt an alert by switching the receiver off or leaving range for more than 30 minutes. When you return, the old alert must not replay. The receiver should show only Welcome back with a count, and no notification text. If you can, repeat this once with the app force-stopped while away, and once with the phone restarted.
  8. Alert-delivery notification. On Android 8 or later, check that a Bluetooth Alert · Delivering an alert notification appears while an alert plays and disappears when it ends. This matters most on Android 15.
  9. Save the app's field-test package (optional). Before step 3, you can tap Start Field Test on the main screen, leaving the vehicle text boxes empty. When you finish, tap Finish, Save & Share ZIP and choose your email app. The package contains only structured checks; photos, notification text, Bluetooth names, typed vehicle details and raw logs are excluded by the app.

If something does not work

The APK will not install

Check that you downloaded it on Android and allowed installation from the browser or file app you used. Record “Installation failed” if it still fails. If Android reports an incompatible update or conflicting signature, report that before uninstalling; uninstalling can remove local test records. Do not disable Android's security protections to force installation.

The receiver is missing, or the test button is disabled

Check that Bluetooth is on, Nearby devices/Bluetooth access is allowed, the receiver is paired and connected for music, and the receiver is set to Bluetooth Audio. Disconnect other audio receivers and tap Refresh bonded endpoints. If the button remains disabled, report it. Do not confirm a feature just to enable the button.

The phone shows a title, but the receiver does not

Check the receiver's music/title screen rather than its phone-call screen. Dismiss the alert, reconnect Bluetooth, refresh the inspector, and try one more generated test. Report “Title did not appear” if it still does not show. This is useful evidence, not a reason to keep retrying indefinitely.

Android blocks notification access

The basic test works without notification access. For the recovery tests, some Android versions require Allow restricted settings under Settings → Apps → Bluetooth Alert → the three-dot menu first. That option is not on every phone; if it is absent or blocked, record it and skip the recovery tests.

I do not know the model or Bluetooth version

Use “Unknown.” A generic product model, such as “Toyota factory stereo” or “Sony speaker,” is enough to start. You do not need to look up technical profiles or Bluetooth versions. Do not use a personalized Bluetooth name such as a person's phone or car name.

4. Report your results by email

Fill in what you know below, then tap Email report. It opens your email app with the report filled in. Add the address from your invitation email, attach the app files listed below, check everything, and send. Nothing is sent automatically.

Remove all personal information before you send anything.

We only want test results. Before sending, read the report, every attachment and your email itself, and delete anything personal: names, contacts, phone numbers, email addresses other than your own sender address, notification or message text, locations, license plates, VINs, serial numbers, IMEI, MAC/Bluetooth addresses, and personalized device names such as “Sam's car”. Remove your email signature too. If you are unsure whether something is personal, delete it or leave that file out.

Attach only these files from beta.6: the privacy-safe capability report (text), the field-test package whose name starts with safe-v2_, and, if asked, the text from ▶ Debug logs → Copy logs pasted into the email. These are designed not to contain message content, but please still check them. Do not send screenshots, photos, screen recordings, or ZIP files from older app versions.
