Help test Bluetooth Alert

Bluetooth Alert aims to show permitted phone alerts on compatible Bluetooth media screens — for example, in the space normally used for a song title. We need your help finding out what actually works on different receivers.

No Bluetooth expertise or extra hardware is needed. Use an Android phone and a Bluetooth car, boat, motorcycle system, stereo, speaker, or headset you already have. This APK cannot be installed on an iPhone.

1. Install and connect

  1. Download on your Android phone. Open this page on the phone, tap the download button, then open app-debug.apk from the browser's Downloads list. If Android asks, allow this browser or file app to install this APK. You can turn that permission off afterward. If installation fails, record the error category in the report below.
  2. Open Bluetooth Alert and note its version. The version is shown near the top of the app. Copy it into the report below; if you cannot install the app, use the version on the release page.
  3. Pair normally. Use Android Settings → Bluetooth and the receiver's normal pairing menu. For the first test, disconnect other Bluetooth audio receivers from the phone. On the receiver, select Bluetooth Audio, Media, or the equivalent music source. Phone-call pairing alone may not connect Bluetooth music.
  4. Allow Bluetooth access when prompted. Android may call it Nearby devices. Start with the app's generated test alerts: notification access is not needed for this test. Leave access to your personal notifications off for the beginner test.

2. Run a simple test

Use one receiver per report. “Receiver” just means the Bluetooth device you are testing. It is useful to report failures, unavailable buttons, and devices with no screen too.

  1. Find your receiver in the app. Tap V2 Endpoint Capability Inspector, then Refresh bonded endpoints. Select the connected receiver in the list and tap Run available probes. “Bonded” means paired; “probes” means the app's checks of available functions. Unknown or provisional means a function has not been verified yet.
  2. Send a generated title. Tap Send metadata test in the inspector. On the main screen, the equivalent button may say Verify title on connected endpoint or Send Test Alert. Watch the receiver's music/title screen while the test is active. The generated title contains a test number, such as #1 TEST ALERT — ALPHA; sending another test changes the number.
  3. Record what the receiver actually showed. Was the whole title visible, cut short, missing characters, delayed, or absent? A title in the phone's preview does not prove it reached the receiver. Tap Confirm metadata visible only if you saw it on the receiver. Newer builds may also offer buttons for a missing title, timeout, truncation, or wrong characters; use them if present. If a test button is disabled, report that and continue with the steps you can run.
  4. Try the receiver's media buttons, if it has them. While a test alert is active, try Play, Pause, Next, and Previous, one at a time. Record each separately as worked, no visible effect, button not present, or not tested. Do not mark browsing as confirmed unless you could actually browse alerts on the receiver.
  5. Check recovery. Tap Dismiss alert / Resume media. Disconnect the receiver in Android Bluetooth settings, reconnect it, refresh the inspector, and send another generated test. Record whether it works after reconnecting; do not remove the pairing unless normal reconnection fails.
  6. Optional: check music interruption. Start ordinary music through the receiver, then return to Bluetooth Alert. Select Priority — interrupt media, show alert, then resume, send a test, and dismiss it. Record whether music resumed automatically, needed a manual restart, or did not resume. Stop the test if playback keeps switching between apps.
A speaker with no display can be a useful test. Choose “No display on receiver” in the report. A missing display is different from a receiver with a screen that failed to show a title. This basic test does not verify every audio or voice feature.

If something does not work

The APK will not install

Check that you downloaded it on Android and allowed installation from the browser or file app you used. Record “Installation failed” if it still fails. If Android reports an incompatible update or conflicting signature, report that before uninstalling; uninstalling can remove local test records. Do not disable Android's security protections to force installation.

The receiver is missing, or the test button is disabled

Check that Bluetooth is on, Nearby devices/Bluetooth access is allowed, the receiver is paired and connected for music, and the receiver is set to Bluetooth Audio. Disconnect other audio receivers and tap Refresh bonded endpoints. If the button remains disabled, report it. Do not confirm a feature just to enable the button.

The phone shows a title, but the receiver does not

Check the receiver's music/title screen rather than its phone-call screen. Dismiss the alert, reconnect Bluetooth, refresh the inspector, and try one more generated test. Report “Title did not appear” if it still does not show. This is useful evidence, not a reason to keep retrying indefinitely.

Android blocks notification access

You can still run the generated Bluetooth title test without notification access. If you later choose to test real notifications, use Grant notification access in the app. Some Android versions may offer Allow restricted settings under Settings → Apps → Bluetooth Alert → the three-dot menu. That option is not available on every phone; if it is absent or blocked, record it rather than assuming the Bluetooth test failed. Notification access exposes notification content to the app, so enable it only if you want that separate test.

I do not know the model or Bluetooth version

Use “Unknown.” A generic product model, such as “Toyota factory stereo” or “Sony speaker,” is enough to start. You do not need to look up technical profiles or Bluetooth versions. Do not use a personalized Bluetooth name such as a person's phone or car name.
